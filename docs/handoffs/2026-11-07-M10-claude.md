## Summary
- `src/cloth_segment/rawclass.py`: three generic helpers next to the M6 `accessory` code.
  - `raw_pred_matrix(pred, raw)`: pixel counts, raw id × predicted shared class. It covers every pixel, also raw classes that map to IGNORE.
  - `shared_counts(pred, target)`: ground-truth, predicted and true-positive pixels per shared class. IGNORE is skipped, as in `evaluate.confusion_matrix`.
  - `raw_rows(matrix, dataset)`: one row per raw class present, with the shared class it maps to and how many of its pixels were predicted as that class.
- `scripts/raw_class_breakdown.py`: thin CLI over these helpers, using the M6 eval path (`raw_loader`, `iter_predictions`). For each run and test set it writes to `--out-dir`:
  - `raw_confusion.json`: per raw class, its pixels, recall and where its pixels went;
  - `per_image_shared.csv` and `per_image_raw.csv`: pixel counts per image, used for grouping by object size and for picking images to look at.
- `tests/test_rawclass.py`: 4 new tests, no GPU or real data.
- Nothing changes labels, splits, the eval protocol or any run folder.

## Decisions and why
- **Generic, not one script per question.** The model reports raised concerns about several classes. One breakdown of every class answers them all from one GPU pass per run, and covers classes nobody has asked about yet.
- **Cross-check against saved metrics.** The script sums its per-image counts and compares them with each run's `eval/eval-v2/<dataset>/metrics.json` (row sums, column sums, diagonal). It exits with code 1 on any mismatch. So its numbers use the same predictions as the reported metrics.
- **Output outside the repo and outside `runs/`.** It writes pixel counts only, no images (dataset licences). Finished run folders are not touched (D7).
- **Runs: X2, X3, X4.** These are the three runs being compared (`eval-v2`, seeded init). X1 is left out.

## Results / findings
Q5 and Q6 were checked from existing files, without the GPU. Q1–Q4: to be added.

**Q5: the X3 DFMM drops are larger than U-Net run-to-run noise.** X1 and X2 have the same config and are both scored at `best.pt` step 40000 (X1 `eval-v1`, X2 `eval-v2`). M3 changed only checkpoint selection and the `metrics.json` format; test scoring is the same in both versions, so the two can be compared. Test IoU on DFMM:

| class | X2 − X1 (noise) | X3 − X2 |
|---|---|---|
| hair | +0.0013 | −0.0124 |
| skin | +0.0005 | −0.0125 |
| footwear | −0.0005 | −0.0110 |
| headwear | +0.0078 | −0.0228 |
| skirt | −0.0040 | +0.0472 |

Except for `accessory`, |X2 − X1| is at most 0.0078 for every DFMM class. Caveat: this noise comes from one pair of U-Net runs; DeepLabV3+ may vary more between runs.

**Q6: no.** From `data/splits/splits-v2/manifest.csv` (`accessory_supply`), DFMM `accessory` has 455 train images, 57 val and 72 test (5.6% of 1,293 test images), with 157,182 test pixels (0.015% of labelled pixels). Between the two U-Net runs alone, DFMM `accessory` IoU changes by −0.207.

## Gotchas
- Needs the GPU lock (`runs/.gpu.lock`); the script takes it itself. Add `--wait` to queue behind another job.
- The command:
  ```bash
  uv run python scripts/raw_class_breakdown.py \
    20261105-1307-1acb88f-unet-r34 20261105-2050-f4e2ffe-deeplabv3p-r50 \
    20261105-2220-ac9a26b-segformer-b2 --out-dir <dir outside the repo>
  ```
- X4 was trained on another machine (`lemasc-ubuntu`, RTX 3060). This pass runs inference for all three runs on `METAVERSE-05` (RTX 4070). The cross-check shows whether the predictions match the saved metrics exactly.
