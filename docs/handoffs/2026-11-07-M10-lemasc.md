# Handoff — M10 Data concerns from model results (lemasc)

**สถานะ:** `done` ตอบคำถาม Q1–Q6 ครบแล้ว maintainer (ผู้ดูแลโปรเจกต์) ดูรูปของ Q2–Q4 ครบทั้ง 72 รูป และตัดสินใจ d1–d4 แล้ว รายงานฉบับเต็มอยู่ที่ `docs/reports/2026-11-07-M10-data-concerns.md`

## In plain words
เทรนโมเดลครบทั้งสามตัวแล้ว (X2 U-Net, X3 DeepLabV3+, X4 SegFormer) M10 ตรวจว่าผลที่ต่ำในบางคลาสมาจากข้อมูล (label, การรวมคลาส, ขนาดของวัตถุ) ไม่ใช่จากโมเดลหรือเปล่า
งานนี้เพิ่มสคริปต์ที่แยกผลทำนายบน test ของแต่ละ run ตาม raw class (คลาสเดิมของ dataset ก่อนรวม) และตามรูป และเพิ่ม marimo notebook ไว้ดูรูปตัวอย่าง
สิ่งที่พบ:
- jumpsuit ของ LIP (ซึ่ง map เป็น `dress`) ถูกทายเป็นเสื้อ + กางเกงบ่อยกว่าชุดเดรสจริงมาก
- รองเท้าใน CIHP ตัวเล็ก ซึ่งอธิบายได้ว่าทำไม recall ต่ำ ที่ขนาดเท่ากัน CIHP ก็ยังต่ำกว่า LIP แต่ส่วนนี้อาจมาจากขนาดเหมือนกัน (หนึ่งรูปมีหลายคน)
- "ถุงเท้า" ใน CIHP หลายครั้งเป็นถุงน่อง ถุงเท้ายาว หรือดูเหมือนขาเปล่า โมเดลเลยทายเป็นกางเกงหรือผิวหนัง
- skirt หายไปเป็น dress ในรูปที่ยากที่สุดและใน U-Net ส่วน X4 เสีย skirt ให้ pants มากกว่าในรูปทั่วไป
- outer → upper ส่วนใหญ่เป็นความผิดของโมเดล

ไม่ต้องเทรนใหม่ T9 และ T10 จะรายงานคะแนนเพิ่มและเขียนข้อจำกัด

## Summary
- `src/cloth_segment/rawclass.py`: ฟังก์ชันทั่วไปสามตัว วางไว้ข้างโค้ด `accessory` ของ M6
  - `raw_pred_matrix(pred, raw)`: นับพิกเซลเป็นตาราง raw id × คลาสร่วมที่ทาย นับทุกพิกเซล รวมถึง raw class ที่ map เป็น IGNORE
  - `shared_counts(pred, target)`: จำนวนพิกเซล ground truth, ที่ทาย และที่ทายถูก (true positive) ต่อคลาสร่วม ข้าม IGNORE เหมือน `evaluate.confusion_matrix`
  - `raw_rows(matrix, dataset)`: หนึ่งแถวต่อ raw class ที่มีอยู่ บอกว่า map ไปคลาสร่วมไหน และมีกี่พิกเซลที่ถูกทายเป็นคลาสนั้น
- `scripts/raw_class_breakdown.py`: CLI บาง ๆ ครอบฟังก์ชันข้างบน ใช้เส้นทาง eval ของ M6 (`raw_loader`, `iter_predictions`) สำหรับแต่ละ run และ test set จะเขียนลง `--out-dir`:
  - `raw_confusion.json`: ต่อ raw class มีจำนวนพิกเซล recall และพิกเซลไปอยู่คลาสไหน
  - `per_image_shared.csv` และ `per_image_raw.csv`: จำนวนพิกเซลรายรูป ใช้จัดกลุ่มตามขนาดวัตถุและเลือกรูปมาดู
- `tests/test_rawclass.py`: test ใหม่ 5 ตัว ไม่ใช้ GPU หรือข้อมูลจริง
- การดูรูปด้วยตา (โฟลเดอร์มาจาก PR #25):
  - `configs/review/m10.yaml`: run ที่ใช้ คำถาม วิธีเลือกรูป รหัสคำตัดสิน (verdict) และตัวเลือกการตัดสินใจ
  - `src/cloth_segment/review.py`: เลือกรูป จัดกลุ่มตามพื้นที่ ตัวชี้วัดแทนถุงเท้า/ถุงน่อง (`socks_context`) การวาด (overlay สีของ label ร่วมและ raw, เส้นขอบ, crop) คำอธิบายสีของ raw label อ่านและเขียนคำตัดสิน และนับผล test อยู่ใน `tests/test_review.py` (21 ตัว ไม่ใช้ GPU หรือข้อมูลจริง)
  - `scripts/review_predictions.py`: เขียน `data/review/M10/samples.csv` (96 รูป) และ mask ที่ X2–X4 ทายสำหรับรูปเหล่านั้น (`data/review/M10/pred/<alias>/<dataset>/<index>.png`)
  - `notebooks/review/m10_data_concerns.py` (marimo) เรียงตามนี้:
    1. คำถาม พร้อม IoU ที่ทำให้สงสัย
    2. ผลที่ตอบแล้ว (Q1, Q2, Q5, Q6) คำนวณจากไฟล์
    3. การรวม label บน train split: raw class ไหนประกอบเป็น dress, skirt, pants, upper, outer, footwear และ skin ในแต่ละ dataset (`merge_composition` ของ M5 บน `data/eda/scan_*.csv`)
    4. รูปที่ต้องดู 96 รูป แยกแท็บตามคำถาม แต่ละรูปมี: รูปถ่าย (ซูมเมื่อคลาสตัวเล็ก), ground truth, raw label พร้อมคำอธิบาย (ชื่อ raw → คลาสร่วม, สัดส่วนพื้นที่) และผลทายของ X2/X3/X4 มี slider ปรับขนาดภาพและความทึบของ mask คลิกที่รูปจะเปิดภาพขนาดเต็มในแท็บใหม่
    5. ผลนับคำตัดสินที่อัปเดตตลอด และแต่ละ run ทายพิกเซลที่ดูแล้วเป็นอะไร แยกตามคำตัดสิน โดยแยกชุดสุ่มกับชุดแย่สุดออกจากกัน (`review.pred_shares`, `review.verdict_shares`) ตามด้วยการตัดสินใจ

    คำตัดสิน โน้ต และเครื่องหมายติ๊ก บันทึกลง `docs/reports/2026-11-07-M10-verdicts.csv` ทันที (คอลัมน์ `question, key, verdict, note` ติ๊กการตัดสินใจคือ `verdict = x`)
- ไม่มีอะไรเปลี่ยน label, split, eval protocol หรือ run folder

## Decisions and why
- **ทำแบบทั่วไป ไม่ทำสคริปต์แยกต่อคำถาม** รายงานของโมเดลตั้งข้อสงสัยไว้หลายคลาส การแยกผลทุกคลาสครั้งเดียวตอบได้ทุกข้อ จาก GPU รอบเดียวต่อ run และครอบคลุมคลาสที่ยังไม่มีใครถามด้วย
- **ตรวจกับ metrics ที่บันทึกไว้** สคริปต์รวมจำนวนรายรูปแล้วเทียบกับ `eval/eval-v2/<dataset>/metrics.json` ของแต่ละ run (ผลรวมแถว ผลรวมคอลัมน์ เส้นทแยง) ถ้าไม่ตรงจะออกด้วย exit code 1 ตัวเลขจึงมาจากผลทายชุดเดียวกับ metrics ที่รายงาน
- **ผลลัพธ์อยู่ใน `data/review/M10/` ไม่อยู่ใน repo หรือ `runs/`** มีแค่จำนวนพิกเซลและ mask ที่ทาย ไม่ commit รูปใด ๆ (ติดลิขสิทธิ์ dataset) ไม่แตะ run folder ที่เสร็จแล้ว (D7) สคริปต์ไม่เขียนทับของเดิม: `raw_class_breakdown.py` จะหยุด (exit code 3) ถ้ามีไฟล์ผลลัพธ์อยู่แล้ว ก่อนจะจอง GPU lock ส่วน `review_predictions.py` จะหยุดถ้า `samples.csv` ไม่ตรงของเดิม และข้าม mask ที่มีอยู่แล้ว
- **รูปตัวอย่าง: "แย่สุด" 12 รูป + สุ่ม 12 รูป ต่อคำถาม** "แย่สุด" คือ recall ของ X4 ต่ำที่สุด ในรูปที่คลาสนั้นกินพื้นที่อย่างน้อย `min_share` ของรูป X4 เป็นโมเดลที่ดีที่สุด จุดที่ X4 พลาดจึงน่าจะมาจากข้อมูลมากที่สุด ชุดสุ่มช่วยไม่ให้นับ label ผิดเกินจริง seed และกฎอยู่ใน config
- **notebook ไม่วาดรูปใหม่เมื่อเปลี่ยนคำตัดสิน** marimo จะรันทุก cell ที่ใช้ widget ใหม่ ยกเว้น cell ที่สร้าง widget นั้น เราจึงสร้าง widget คำตัดสินใน cell ของรูป และเมื่อ slider ทำให้ cell นั้นรันใหม่ widget จะเริ่มจากค่าในไฟล์คำตัดสิน รูปจะวาดเมื่อเลื่อนมาถึงเท่านั้น (`mo.lazy`)
- **ตรวจผลทายที่บันทึกไว้** เทียบ mask ที่บันทึกแต่ละอันกับจำนวนจาก breakdown ของ run เดียวกัน ราย raw class ตรงกันครบทั้ง 288 อัน (96 รูป × 3 run)
- **ใช้ run X2, X3, X4** เป็นสาม run ที่เราเปรียบเทียบกัน (`eval-v2`, init แบบกำหนด seed) ไม่ใช้ X1

## Results / findings
Q5 และ Q6 ตรวจจากไฟล์ที่มีอยู่ ไม่ใช้ GPU ส่วน Q1 และ Q2 มาจากการรันบน GPU (ผลของ `scripts/raw_class_breakdown.py` ใน `data/review/M10/breakdown/`) ผลการดูรูปของ Q2–Q4 อยู่ท้ายหัวข้อนี้ และฉบับเต็มอยู่ในรายงาน
ค่าเรียงเป็น X2 / X3 / X4 ถ้าตารางไม่ได้บอกเป็นอย่างอื่น "recall" ของ raw class คือสัดส่วนพิกเซลของมันที่ถูกทายเป็นคลาสร่วมที่มัน map ไป raw class ไม่มี precision หรือ IoU ของตัวเอง เพราะพิกเซลที่ทายผิดไม่มี raw class

**Q1: jumpsuit ของ LIP เป็นสาเหตุจริงส่วนหนึ่งที่ทำให้ LIP `dress` ต่ำ แต่ไม่ใช่ทั้งหมด**

| raw class (test) | map เป็น | พิกเซล | recall | ที่เหลือส่วนใหญ่ไปที่ |
|---|---|---|---|---|
| LIP dress | dress | 7,349,016 | 0.49 / 0.55 / 0.60 | upper 0.16–0.21, background 0.10–0.12 |
| LIP jumpsuits | dress | 3,312,565 | 0.24 / 0.39 / 0.42 | pants 0.19–0.26, upper 0.19–0.24 |
| CIHP dress | dress | 17,351,843 | 0.64 / 0.68 / 0.70 | upper 0.12–0.14 |
| DFMM dress | dress | 30,180,645 | 0.90 / 0.90 / 0.91 | |
| DFMM rompers | dress | 6,522,575 | 0.93 / 0.95 / 0.95 | |

- jumpsuit เป็น 31% ของพิกเซล `dress` ใน LIP test recall ต่ำกว่าเดรสของ LIP 0.18–0.25 และพิกเซลที่พลาดไปอยู่ที่ upper + pants ซึ่งเป็นวิธีที่ CIHP label jumpsuit (T2) ข้อมูลเทรนจึงสอนคำตอบไว้สองแบบ
- romper ของ DFMM หาได้ง่าย (0.93–0.95) แปลว่าชุดชิ้นเดียวไม่ได้ยากเสมอไป T1 บอกว่า jumpsuit ของ LIP คือชุดดำน้ำ ชุดเบสบอล ชุดหมี และชุดคอสตูม ซึ่งดูเหมือนเสื้อกับกางเกง
- เดรสจริงของ LIP ก็ยังต่ำกว่าเดรสของ CIHP (0.49–0.60 เทียบ 0.64–0.70) jumpsuit อธิบายช่องว่างของ LIP ได้บางส่วน ไม่ใช่ทั้งหมด

**Q2: ขนาดเล็กอธิบายช่องว่างของรองเท้า CIHP ได้มาก แต่ยังไม่ชัดว่าทั้งหมด ส่วนถุงเท้า CIHP พลาดด้วยเหตุผลอื่น**

recall ต่อ raw class (รองเท้าซ้ายและขวาต่างกันไม่เกิน 0.02 จึงรวมกัน):

| test set | shoes | socks | สัดส่วน socks ในพิกเซล `footwear` |
|---|---|---|---|
| LIP | 0.71 / 0.70 / 0.76 | 0.71 / 0.69 / 0.77 | 17% |
| CIHP | 0.55 / 0.56 / 0.67 | 0.25 / 0.32 / 0.45 | 25% |
| DFMM (footwear) | 0.91 / 0.91 / 0.93 | 0.96 / 0.94 / 0.95 | 3% (+ leggings 6%) |

พิกเซลรองเท้า CIHP ที่พลาดไปอยู่ที่ `background` เป็นส่วนใหญ่ (0.23–0.33) พิกเซลถุงเท้า CIHP ที่พลาดไปอยู่ที่ `skin` (0.16–0.29) และ `pants` (0.22–0.25)

recall ของรองเท้าแยกตามขนาด วัดจากพิกเซลรองเท้าในรูปหารด้วยพื้นที่รูป (X2 / X4):

| พื้นที่รองเท้า | < 0.4% | 0.4–0.8% | 0.8–1.6% | 1.6–3.2% | > 3.2% | ค่ามัธยฐาน |
|---|---|---|---|---|---|---|
| LIP | 0.36 / 0.40 | 0.52 / 0.57 | 0.66 / 0.72 | 0.75 / 0.80 | 0.70 / 0.75 | 2.46% |
| CIHP | 0.31 / 0.37 | 0.47 / 0.56 | 0.57 / 0.66 | 0.61 / 0.72 | 0.52 / 0.71 | 0.89% |
| DFMM | 0.64 / 0.64 | 0.76 / 0.82 | 0.91 / 0.93 | 0.96 / 0.96 | 0.93 / 0.97 | 1.19% |

จำนวนรูปต่อกลุ่ม LIP / CIHP / DFMM: < 0.4%: 166 / 427 / 92; 0.4–0.8%: 249 / 414 / 207; 0.8–1.6%: 860 / 559 / 695; 1.6–3.2%: 2,315 / 344 / 259; > 3.2%: 1,605 / 80 / 21

- recall สูงขึ้นตามขนาดในทั้งสาม dataset และรองเท้าใน CIHP เล็กกว่า (ค่ามัธยฐาน 0.89% ของรูป เทียบ 2.46% ใน LIP)

## Gotchas
- ทั้งสองสคริปต์ต้องใช้ GPU lock (`runs/.gpu.lock`) และจองเอง ใส่ `--wait` เพื่อต่อคิวหลังงานอื่น
- ถ้าจะรัน breakdown ใหม่ ให้ใช้ `--out-dir` ใหม่ สคริปต์จะไม่เขียนทับ `data/review/M10/breakdown/`
- คำสั่งตามลำดับ:
  ```bash
  uv run python scripts/raw_class_breakdown.py \
    20261105-1307-1acb88f-unet-r34 20261105-2050-f4e2ffe-deeplabv3p-r50 \
    20261105-2220-ac9a26b-segformer-b2 --out-dir data/review/M10/breakdown
  uv run python scripts/review_predictions.py configs/review/m10.yaml
  uv run marimo edit notebooks/review/m10_data_concerns.py
  ```
- หลังแก้ notebook ให้ restart marimo (หยุดแล้วรัน `marimo edit` ใหม่) จึงจะโหลดของใหม่ คำตัดสินไม่หาย เพราะอยู่ใน CSV
- อ่าน CSV รายรูปด้วย `dtype={"id": str}` ไม่อย่างนั้น id ของ CIHP เช่น `0000001` จะเสียเลข 0 ข้างหน้า
- X4 เทรนและวัดผลบนอีกเครื่อง (`lemasc-ubuntu`, RTX 3060) แต่รอบนี้รันบน `METAVERSE-05` (RTX 4070) X2 และ X3 ตรงกับ metrics ที่บันทึกไว้ทุกตัว แต่ X4 ไม่ตรง สคริปต์จึงออกด้วย exit code 1 จำนวน ground truth ตรงกันทุกตัว พิกเซลที่ทายต่างกันมากสุด 5,506 พิกเซลต่อ test set (จาก 0.7–1.1 พันล้าน) IoU รายคลาสต่างกันมากสุด 0.00044 และ mIoU ต่างกันไม่เกิน 0.00006 เป็นความต่างเชิงตัวเลขของ GPU เล็กเกินกว่าจะเปลี่ยนข้อสรุปใดในงานนี้
- เวลารันบน RTX 4070: X2 และ X3 ประมาณ 1.5 นาทีต่อตัวสำหรับ test ทั้งสามชุด X4 ประมาณ 3 นาที
- ใน pandas อย่าอ่านคอลัมน์ `gt` ด้วย `df.gt` เพราะนั่นคือ method "greater than" ให้ใช้ `df["gt"]`

## Decisions by the maintainer
บันทึกไว้ในไฟล์คำตัดสิน (`d1`–`d4`) ไม่เปลี่ยน contract ที่ frozen และไม่เทรนใหม่ ทางเลือก frozen-change (เช่น map LIP `jumpsuits` และ CIHP `socks` เป็น IGNORE แล้วเทรนใหม่) ถูกปฏิเสธ เพราะการ map ใหม่แก้ปัญหาทั้งสองได้ไม่หมด jumpsuit ของ CIHP ถูก label เป็น upper + pants ไปแล้ว ไม่มีการ map แบบไหนหามันเจอ ส่วน CIHP `socks` รวมถุงเท้าจริงกับถุงน่องไว้ใน raw class เดียว รายละเอียดอยู่ในรายงาน หัวข้อการตัดสินใจ
- d1 jumpsuit ของ LIP: เขียนเป็นข้อจำกัด (T10) และ T9 รายงาน LIP `dress` แบบไม่นับพิกเซล jumpsuit เพิ่มด้วย ไม่ได้ดูรูปของ Q1 ตัดสินจากตัวเลข
- d2 socks ของ CIHP: เขียนเป็นข้อจำกัด (T10) และ T9 รายงาน CIHP `footwear` แบบไม่นับพิกเซล socks เพิ่มด้วย
- d3 skirt: เขียนเป็นข้อจำกัด (T10) สำหรับ skirt กับ dress และกระโปรงที่ดูเหมือนกางเกงขาสั้น กระโปรงที่ชัดเจนนับเป็นความผิดของโมเดลใน error analysis
- d4 outer: นับเป็นความผิดของโมเดลใน error analysis
