# Handoff — M11 ตรวจคนอื่นในภาพ LIP (lemasc)

## สรุปสั้น ๆ
ผมตรวจสมมติฐานของ T10 ที่ว่า ข้อผิดพลาดของ background ด้านในบน LIP คือคนอื่นที่ LIP ไม่ได้ label ผลคือสมมติฐานเป็นจริง: ใน 30 ภาพที่มีข้อผิดพลาดแบบนี้มากที่สุด โมเดลแยกส่วนของคนอื่นใน 24 ภาพ
ถ้าไม่นับพื้นที่ใหญ่เหล่านี้ mIoU ของ LIP จะสูงขึ้นประมาณ 0.04–0.05 กับทุกโมเดล แต่ลำดับและช่องว่างระหว่างโมเดลไม่เปลี่ยน นี่คือความขัดแย้งของกฎการทำ label ระหว่าง LIP กับ CIHP เราจึงบันทึกเป็นข้อจำกัดและไม่แก้อะไร
รายงาน: `docs/reports/2026-11-08-M11-lip-multiperson.md` ขั้นต่อไป: T11 ใช้เป็นสไลด์ได้

## สรุปงาน
- `src/cloth_segment/multiperson.py`: ฟังก์ชันล้วน (pure function) สำหรับนับพิกเซลคนผิด การทดสอบแบบเข้ม "คนละก้อน" กฎ blob-ignore ความกระจุกตัว การเลือกตัวอย่างตรวจ และการนับคำตัดสิน
- `scripts/multiperson.py` (ใช้ GPU ต้องมี lock): ทำนายใหม่ และเขียน `data/analysis/M11/<run>/<ds>.json` (confusion matrix รวม พร้อมการเทียบกับ `metrics.json`) กับ `.csv` (จำนวนต่อภาพ) แยกตาม run และชุดทดสอบ และเก็บผลทำนาย LIP ของ X4 ไว้ที่ `data/review/M11/pred/`
- `scripts/m11_results.py` (ไม่ใช้ GPU): เขียน `docs/reports/2026-11-08-M11-results.json` และ `-tables.md` กับ `data/review/M11/samples.csv` ถ้าใส่ `--sheets` จะวาด sheet สำหรับตรวจด้วย (เป็นภาพจากชุดข้อมูล ไม่ commit)
- `configs/report/m11.yaml`: run, กฎ, threshold และ path
- `docs/reports/2026-11-08-M11-verdicts.csv`: คำตัดสินของ 45 ภาพ
- Test: `tests/test_multiperson.py` (10 test ใช้ข้อมูลสังเคราะห์)

## การตัดสินใจและเหตุผล
- **ด้านใน (interior) = อยู่นอกแถบขอบ 1% ของ T10** เพื่อให้เทียบกับ T10 ได้ และแยกปัญหานี้ออกจากข้อผิดพลาดที่ขอบ
- **คะแนน blob-ignore เป็นขอบบน ไม่ใช่คะแนนทางการ** กฎนี้แยกคนอื่นออกจากวัตถุหรือคนหลักที่ไม่ถูก label ไม่ได้ ส่วนกฎแบบเข้ม (คนที่ทำนายแล้วไม่แตะคนที่ถูก label) พบเพียง 12–14% ของพิกเซล จึงไม่ใช้คิดคะแนน
- **คำตัดสิน:** Claude subagent อ่านครบ 45 ภาพในการสืบค้นก่อนงานนี้ ตัวอย่างของมันตรงกับที่โค้ดนี้เลือกทุกประการ (id และจำนวนเท่ากัน) ผมตรวจซ้ำ 18 ภาพและแก้หนึ่งภาพ (#40) จากนั้น lemasc ดูครบทั้ง 8 sheet และแก้ #26 กับ #29 (GT ไม่ได้ label คนหลักของภาพ) เป็น `main_annotation_missing` CSV เก็บการอ่านครั้งแรก ภาพที่ตรวจซ้ำ และคำตัดสินสุดท้าย เหมือนที่ T10 ทำ
- **ไม่เปลี่ยนชุดทดสอบหรือ protocol:** CONTRIBUTING หัวข้อ 4 ห้ามเปลี่ยนชุดทดสอบเพื่อให้ตัวเลขดีขึ้น และไม่แตะ contract ที่ frozen

## ผลและสิ่งที่พบ
Run X2/X3/X4 เหมือน T10 การทำนายเพื่อวิเคราะห์รันบน RTX 4070
- พิกเซลคนผิดด้านในต่อพิกเซล GT background: LIP 0.061–0.071, CIHP (X4) 0.015
- สำหรับ X4 บน LIP ภาพ 10% แรกมี 71% ของพิกเซลเหล่านี้
- mIoU 11 คลาส ที่ blob ≥ 1%: X2 0.5924→0.6386, X3 0.6071→0.6506, X4 0.6399→0.6838, X4 CIHP 0.6682→0.6781 X4 − X2 คือ +0.047 ในคะแนนทางการ และ +0.045 ที่นี่
- คำตัดสิน: 28 คนอื่น, 6 คนหลักไม่ถูก label, 4 วัตถุ, 7 ไม่ชัดเจน
- `dress` และ `skirt` แทบไม่เปลี่ยน ปัญหานี้จึงไม่ใช่เหตุผลที่สองคลาสนั้นต่ำ

## ข้อควรระวัง
- `scripts/multiperson.py` ไม่เขียนทับ: ถ้ามี `data/analysis/M11/<run>/<ds>.json` อยู่แล้ว จะข้าม run และชุดทดสอบนั้น ถ้าต้องรันใหม่ ให้ลบเฉพาะผลลัพธ์ของตัวเอง
- `m11_results.py` ไม่ยอมเขียน `samples.csv` ถ้ามีไฟล์เดิมที่ตัวอย่างต่างกัน ให้เปลี่ยน `review.out_dir` เพื่อวาดชุดใหม่
- matrix ของ X4 ไม่ตรงกับ `metrics.json` ทุกค่า: `check_vs_saved_metrics` เป็น `same_matrix: false` ต่างสูงสุด 2,359 / 2,898 พิกเซล สาเหตุคือรุ่น GPU (3060 กับ 4070) ไม่ใช่บั๊ก ส่วน X2 และ X3 ตรงทุกค่า
