# Handoff — X5 SegFormer-B2 multi-task + attribute heads (lemasc)

## In plain words
เทรน `segformer_b2_mt` (E1) ครบ 40k iteration บน RTX 4070 ด้วย seed 1 แล้ว วัดผลบน test ทั้ง segmentation และ attribute
segmentation mIoU: LIP 0.6154, CIHP 0.6305, DFMM 0.8394 · attribute macro-F1 เฉลี่ย 0.8036 (ทายคลาสหลัก 0.3310)
ยังบอกไม่ได้ว่า multi-task ช่วยหรือเสีย segmentation ต้องรอ X6 ซึ่งเป็น run อ้างอิง seed 1 บน GPU เดียวกัน

## Summary
- เทรนและ evaluate ตามขั้นตอนใน CONTRIBUTING section 7: เทรนก่อน แล้วรัน `evaluate` และ `attr_eval`

- รายงานเต็ม: [`docs/reports/2026-11-08-X5-segformer-b2-mt.md`](../reports/2026-11-08-X5-segformer-b2-mt.md)
- ไม่ได้แก้โค้ด config หรือ shared contract ใด ๆ งานนี้เป็น X row (รันอย่างเดียว) และแก้ `docs/PLAN.md` เฉพาะแถว X5

## Decisions and why
- **ไม่ใช้ `--wait`** ตอนเทรน เพื่อให้ job ล้มทันทีถ้ามีคนถือ GPU lock อยู่ แทนที่จะรอเงียบ ๆ (`train.py` ถือ lock เองอยู่แล้ว)
- **ไม่เทียบ X5 กับ X4 เป็นข้อสรุป** เพราะ seed และ GPU ต่างกัน ใส่ X4 ไว้เป็นข้อมูลประกอบเท่านั้น การเทียบจริงรอ X6
- **ไม่ประมาณตัวเลขที่ไม่ได้วัด** เช่น ผลของ attribute head ต่อ error ระหว่าง `outer` กับ `upper` จึงเขียนว่ายังไม่รู้

- เวลา: เทรน 8,417.5 วินาที, val ระหว่างเทรน 567.6 วินาที (ประมาณ 2.3 ชั่วโมงเทรน ตรงกับที่ E1 วัดไว้)
- ที่มา: `meta.json`, `log.jsonl`, `eval/eval-v2/*/metrics.json`, `eval/attr-v1/dfmm/attr_metrics.json`

## Gotchas
- ตอนเทรน log มี `seg_loss`, `attr_loss` และ `attr_images` (จำนวนภาพ DFMM ต่อ batch ประมาณ 1.3–1.8) ไม่ใช่ error
- `evaluate` กับ `attr_eval` ต้องรอ GPU lock เหมือนกัน ใช้ `--wait` ได้ถ้ามีคนใช้ GPU อยู่
- Monitor แต่ละรอบอยู่ได้สูงสุด 30 นาที เทรนรอบนี้ต้อง re-arm หลายครั้ง
