# Handoff — M3 Per-dataset val scores and checkpoint selection (lemasc)

## In plain words
val ระหว่างเทรนเก็บคะแนนแยกรายชุดข้อมูลแล้ว และเลือก `best.pt` จากค่าเฉลี่ย mIoU ของ 3 ชุดข้อมูล (ไม่ใช่ mIoU รวมพิกเซลที่ส่วนใหญ่เป็น DFMM)
`evaluate.py` เป็น contract ที่ `frozen` จึงทำเป็น `frozen-change` และ bump เป็น `eval-v2`
config hash ของทุกโมเดลเปลี่ยน run T6 เดิมจึงไม่ใช่ run ของ config ปัจจุบันแล้ว (ดู "Open items")

## Summary
- Follow-up ข้อ 1 จาก review ของ PR #7 (T6) ดู PR ของ M3
- `evaluate.predict_confusions` คืน confusion matrix แยกรายชุดข้อมูล (ใช้ field `dataset` ที่ `SegDataset` มีอยู่แล้ว)
- `evaluate.val_scores` คำนวณ mIoU รายชุด, mIoU รวม (pooled) และ `dataset_mean_miou`
- `train.fit` เลือก `best.pt` ตาม `eval.select` ค่า default ใหม่ใน `configs/base.yaml` คือ `dataset_mean_miou`
- `python -m cloth_segment.evaluate <run> --split val` ประเมิน `best.pt` บน val รายชุดข้อมูล เขียนที่ `eval/eval-v2/val/<dataset>/metrics.json`
- `evaluate.load_model` สร้างโมเดลด้วย `pretrained: false` ไม่ต้องโหลด weight ImageNet ที่จะถูกเขียนทับ

## Decisions and why
- **ค่าเฉลี่ยรายชุด ไม่ใช่ pooled:** eval-v1 รวมพิกเซลที่ขนาดภาพเดิม ภาพ DFMM ใหญ่กว่า LIP ประมาณ 11 เท่า (ค่าเฉลี่ยจาก test)
  val จึงเป็น DFMM ประมาณ 74% ของพิกเซล (ค่าประมาณ ดู review ของ PR #7) ค่าเฉลี่ยรายชุดให้ทุกชุดมีน้ำหนักเท่ากัน
- **`dataset_mean_miou` เป็น None ถ้าชุดใดไม่มี mIoU:** ไม่อยากให้ชุดที่ไม่มี label หลุดออกจากค่าเฉลี่ยเงียบ ๆ
- **ยังรับ `select: miou`:** เพื่อให้ config ของ run เก่ายังอ่านได้ ไม่ควรใช้กับ run ใหม่
- **การประเมินบน test ไม่เปลี่ยน:** checkpoint เดียวกันให้ตัวเลข test เท่าเดิม ที่ bump version เพราะกฎการเลือก checkpoint และรูปแบบ `metrics.json` เปลี่ยน
- **`metrics.json`:** field `test_set` เปลี่ยนเป็น `dataset` เพิ่ม `checkpoint_select` (ไม่มีโค้ดอื่นอ่าน field เดิม)
