# Handoff — M4 Seed model initialisation; parameter count in meta.json (lemasc)

## In plain words
`train.run` ตั้ง seed ก่อนสร้างโมเดลแล้ว ค่าเริ่มต้นของ layer ที่สุ่ม (decoder และ head) จึงเหมือนกันทุกครั้งที่ใช้ `seed` เดียวกัน
`meta.json` บันทึกจำนวนพารามิเตอร์ (`params`, `trainable_params`) แล้ว
config hash ไม่เปลี่ยน ไม่มีผลกับ contract

## Summary
- Follow-up ข้อ 2 จาก review ของ PR #7 (T6) ดู PR ของ M4
- `train.seeded_model(cfg)`: `torch.manual_seed(cfg["seed"])` แล้ว `build_model(cfg["model"])` และ `train.run` ใช้ตัวนี้
- `train.run` เขียน `params` และ `trainable_params` ลง `meta.json` หลังสร้าง run folder (ใช้ `models.count_parameters`)
- `fit` ยังตั้ง seed ซ้ำก่อนเทรนเหมือนเดิม ลำดับข้อมูลและ augmentation จึงไม่ขึ้นกับจำนวนการสุ่มตอนสร้างโมเดล

## Decisions and why
- **จำนวนพารามิเตอร์อยู่ใน `meta.json` ไม่ใช่ config YAML:** field ใน config ถูก hash (D7) ถ้าใส่ใน YAML จะทำให้ hash เปลี่ยน
- **ตั้ง seed ใน `run` ก่อน `build_model`:** `run` สร้างโมเดลก่อนล็อก GPU เพื่อให้ config ที่ผิด fail เร็ว จึงต้องตั้ง seed ตรงนั้น

## Results / findings
ไม่มี run ใหม่ ไม่ได้รัน GPU

ตรวจบน CPU ด้วย `configs/unet_r34.yaml` (`pretrained: false` เพื่อไม่ต้องโหลด weight):
- สร้าง 2 ครั้งด้วย seed 0 ได้ weight เหมือนกันทุก tensor
- จำนวนพารามิเตอร์ 24,437,964 (trainable ทั้งหมด) ตรงกับที่รายงานใน T6
- config hash `d4f03d515ed0` เท่ากับหลัง M3

## Gotchas
- run ที่เทรนก่อน M4 (T6: `runs/20261105-0323-7b1798b-unet-r34`) สุ่มค่าเริ่มต้นของ decoder และ head โดยไม่ใช้ seed (ดู report ของ T6) รันซ้ำให้ได้ค่าเดิมไม่ได้
- run หลัง M4 กับ run ก่อน M4 ที่ config เดียวกันจะมี hash เดียวกัน แต่ค่าเริ่มต้นต่างกัน ไม่เป็นปัญหาตอนนี้ เพราะ M3 เปลี่ยน hash ไปแล้ว run เก่าจึงไม่ match config ปัจจุบัน
