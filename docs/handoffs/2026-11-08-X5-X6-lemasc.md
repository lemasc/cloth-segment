# Handoff — X5 + X6 SegFormer-B2 multi-task และ run อ้างอิง (lemasc)

## In plain words
เทรน `segformer_b2_mt` (X5, SegFormer-B2 + attribute head 12 ตัว) และ SegFormer-B2 ธรรมดา (X6) ด้วย seed 1 บน RTX 4070 เครื่องเดียวกัน ครบ 40k iteration ทั้งคู่
segmentation mIoU ต่างกันไม่เกิน 0.0009 ต่อ test set (X5 ต่ำกว่าเล็กน้อย) จึงไม่เห็นผลเสียจาก attribute head
attribute macro-F1 เฉลี่ย 0.8036 เทียบ majority baseline 0.3310 · มีแค่ 1 คู่ จึงไม่ใช่ผลทางสถิติ
แยกเป็นสอง PR (X5 แล้ว X6 ซ้อนบน) แต่ handoff นี้รวมสองงานไว้ไฟล์เดียว เพราะผลต้องอ่านเทียบกัน

## Decisions and why
- **สอง PR ซ้อนกัน:** AGENTS.md ให้ใช้หนึ่ง task ID ต่อ branch และ PR จึงแยก X5 (`X5/multitask-segformer-b2`) กับ X6
  (`X6/segformer-b2-seed1`, base คือ branch ของ X5) ให้ merge X5 ก่อน แล้วเปลี่ยน base ของ X6 เป็น `main`
  ตารางเทียบ X5 กับ X6 และ handoff รวมนี้อยู่ใน PR ของ X6 เพราะ X5 สรุปผลไม่ได้ถ้าไม่มี X6 (handoff แยกของ X5 ใน PR ของ X5 ถูกแทนที่ด้วยไฟล์นี้)
- **ไม่ใช้ `--wait` ตอนเทรน:** ให้ล้มทันทีถ้ามีคนถือ GPU lock อยู่ (`train.py` ถือ lock เอง) เครื่องนี้เป็นเครื่องที่ใช้ร่วมกัน
- **ไม่เทียบกับ X4 เป็นข้อสรุป:** X4 ใช้ seed 0 บน RTX 3060 ใช้เป็นข้อมูลประกอบเท่านั้น
- **ไม่ประมาณตัวเลขที่ไม่ได้วัด** เช่น ผลของ attribute head ต่อ error `outer` กับ `upper` จึงเขียนว่ายังไม่รู้

## Results / findings
| test set | mIoU X5 (multi-task) | mIoU X6 (plain) | X5 − X6 |
|---|---|---|---|
| LIP | 0.6154 | 0.6156 | −0.0002 |
| CIHP | 0.6305 | 0.6312 | −0.0007 |
| DFMM | 0.8394 | 0.8404 | −0.0009 |
| เฉลี่ย 12 คลาส | 0.6951 | 0.6957 | −0.0006 |

- ความต่างเล็กกว่าความต่างระหว่าง X4 กับ X6 (สูงสุด 0.0021 บน DFMM) ซึ่งต่างกันที่ seed และ GPU
- attribute (DFMM test, 12 head): accuracy 0.9023, macro-F1 0.8036, majority baseline 0.3310 · head ที่ยากสุดคือ `neckline` (0.4530) และ `waist_acc` (0.6020)
- เวลาเทรน X5 8,417.5 วินาที, X6 8,391.9 วินาที (ต่างกัน 0.3%) พารามิเตอร์ของ X5 เพิ่ม 1.0%
- ที่มา: `meta.json`, `log.jsonl`, `eval/eval-v2/*/metrics.json`, `eval/attr-v1/dfmm/attr_metrics.json`

## Gotchas
- log ของ X5 มี `seg_loss`, `attr_loss` และ `attr_images` (ภาพ DFMM ต่อ batch ประมาณ 1.3–1.8) ไม่ใช่ error
- `evaluate` และ `attr_eval` ต้องรอ GPU lock เหมือนกัน ใช้ `--wait` ถ้ามีคนใช้ GPU
- Monitor อยู่ได้สูงสุด 30 นาทีต่อรอบ แต่ละ run ต้อง re-arm หลายครั้ง
- X6 ไม่มี `attr_eval` เพราะไม่มี attribute head
