# Handoff — M11 LIP multi-person check (claude)

## In plain words
I checked the T10 hypothesis that interior background errors on LIP are other people that LIP does not label. It holds: in 26 of the 30 images with the most of these errors, the model parsed another person.
Ignoring these large areas would raise LIP mIoU by about 0.04–0.05 for every model, but the ranking and the gaps do not change. It is a conflict in labelling rules between LIP and CIHP, so we record it as a limitation and fix nothing.
Report: `docs/reports/2026-11-08-M11-lip-multiperson.md`. Next: T11 can use it as a slide.

## Summary
- `src/cloth_segment/multiperson.py`: pure functions for wrong-person pixels, the strict "separate component" test, the blob-ignore rule, concentration, choosing the review sample and tallying the verdicts.
- `scripts/multiperson.py` (GPU, lock): predicts again and writes per run and test set `data/analysis/M11/<run>/<ds>.json` (summed confusion matrices plus a check against `metrics.json`) and `.csv` (counts per image). It saves X4's LIP predictions to `data/review/M11/pred/`.
- `scripts/m11_results.py` (no GPU): writes `docs/reports/2026-11-08-M11-results.json` and `-tables.md`, plus `data/review/M11/samples.csv`. With `--sheets` it also draws the review sheets (dataset images, not committed).
- `configs/report/m11.yaml`: the runs, rules, thresholds and paths.
- `docs/reports/2026-11-08-M11-verdicts.csv`: verdicts for the 45 images.
- Tests: `tests/test_multiperson.py` (10 tests, synthetic data).

## Decisions and why
- **Interior = outside the T10 1% edge band.** This keeps the result comparable with T10 and separates the problem from boundary errors.
- **The blob-ignore score is an upper bound, not an official score.** The rule cannot tell another person from an object or an unlabelled main person. The strict rule (a predicted person that does not touch the labelled person) finds only 12–14% of the pixels, so I did not use it for the score.
- **Verdicts:** a Claude subagent read all 45 images in an investigation before this task. Its sample is exactly the one this code picks (same ids and counts). I checked 18 of the 45 images and changed one (#40). The CSV keeps the first reading, which images were checked, and the final verdict, as T10 did.
- **No change to the test set or the protocol:** CONTRIBUTING section 4 forbids changing the test set to improve a number, and the frozen contracts stay untouched.

## Results / findings
Runs X2/X3/X4 as in T10. Analysis predictions ran on the RTX 4070.
- Interior wrong-person pixels per GT background pixel: LIP 0.061–0.071, CIHP (X4) 0.015.
- For X4 on LIP, the top 10% of images hold 71% of these pixels.
- mIoU over 11 classes, at blob ≥ 1%: X2 0.5924→0.6386, X3 0.6071→0.6506, X4 0.6399→0.6838, X4 CIHP 0.6682→0.6781. X4 − X2 is +0.047 in the official score and +0.045 here.
- Verdicts: 30 other person, 4 main person not annotated, 4 object, 7 unclear.
- `dress` and `skirt` barely change, so this is not why those classes are low.

## Gotchas
- `scripts/multiperson.py` never overwrites: if `data/analysis/M11/<run>/<ds>.json` exists, it skips that run and test set. Delete only your own outputs if you need to rerun.
- `m11_results.py` refuses to write `samples.csv` if one already exists with a different sample. Change `review.out_dir` to draw a new one.
- X4's matrix does not match `metrics.json` exactly: `check_vs_saved_metrics` is `same_matrix: false` with a max diff of 2,359 / 2,898 pixels. The cause is GPU model (3060 vs 4070), not a bug; X2 and X3 match exactly.
