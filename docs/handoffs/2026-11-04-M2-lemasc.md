# Handoff — M2 Size and shape filter (`splits-v2`)

**Status:** done, PR open. Data version: **`splits-v2-d023252b81d9`**.

## In plain words
LIP has many tiny and very thin crops. We now drop images with a short side
under 64 px or a side ratio above 6:1 from every split, test included. This
removes 1,438 LIP images, 340 of them from the 10,000 test images (368
with the 28 empty-mask ones from M1). CIHP and DFMM lose nothing. New runs must use `splits-v2`; `splits-v1` is untouched.

## Summary
- New rule 6 in `splits.py`: `empty_mask`, `too_small`, `extreme_aspect`
  (`MIN_SIDE = 64`, `MAX_ASPECT = 6.0`). They are written to `meta.json`
  (`scope_rule`).
- Excluded images are removed before the duplicate step: they join no duplicate
  group and cannot make another image a `leak_test`. This also applies to the
  28 empty-mask test images from M1.
- `SPLIT_VERSION` is now `splits-v2`. Built with
  `uv run python scripts/build_splits.py` (55 s). Nothing was trained on v1.

## Decisions and why
- **Same rule for train and test, all datasets** (see D4 and M1). The test set
  should measure clothing parsing on usable images, and a single rule keeps all
  three models on the same data (D5).
- **Thresholds from EDA, not from model scores.** Short side under 64 px: a
  garment gets only a few pixels. Ratio above 6:1: thin strips distort under
  any resize. We chose 64 px because 96 px would cut 13.6% of LIP.
- **Excluded before duplicates.** Otherwise a removed test image would still
  drop its train look-alikes. That is why `leak_test` fell from 2,520 to 2,276
  in LIP.

## Results / findings
Counts come from `data/splits/splits-v2/manifest.csv` (no model runs).

| Dataset | Train | Val | Test | Excluded |
|---|---|---|---|---|
| LIP | 25,653 | 1,358 | 9,632 | 3,819 |
| CIHP | 26,667 | 1,420 | 5,000 | 193 (all leak) |
| DFMM | 10,180 | 1,228 | 1,293 | 0 |

v1 → v2 for LIP: train 26,490 → 25,653, val 1,396 → 1,358, test 9,972 → 9,632.

LIP exclusion reasons (v2): too_small 1,399 (1,060 train, 339 test),
extreme_aspect 39 (38 train, 1 test), empty_mask 105 (77 train, 28 test),
leak_test 2,276. Kept images: smallest short side 64 px, largest ratio 5.97.

- Almost all thin images are also under 64 px on the short side, so the 6:1 rule
  adds only 39 images. It is a safety net, not a big effect.
- 76 train and 2 val images that v1 excluded are now kept, because the test
  image that caused the leak is itself out of scope.

## Gotchas
- LIP test is now 9,632 images, not the official 10,000. Our LIP numbers are not
  comparable to published val numbers. Say so in the report (T9/T10).
- `splits-v1` stays on the shared mount for reference; do not use it for runs.
- Thresholds are constants in `splits.py` (like the duplicate thresholds), not
  YAML, because they define the data version.
