## Rules

1. Test sets:
   - LIP: the official val set (D4).
   - CIHP: the official val set (D4).
   - DFMM: 10% of outfits.
2. Group keys:
   - LIP: the photo, i.e. the first part of the ID `<photo>_<person>`.
   - CIHP: the image.
   - DFMM: the outfit ID.
3. Groups linked by a near-duplicate are merged (union-find).
4. A non-test image whose group contains official test images is
   **excluded** (`leak_test`). The test sets are never changed.
5. Validation sets:
   - LIP/CIHP: 5% of train groups.
   - DFMM: 10% of outfits.
   - Assignment uses a seeded hash of the group key, so it doesn't depend on
     row order.
6. Masks with only background are excluded from every split (`empty_mask`).
   For the test set this is a protocol choice: those masks are annotation
   failures, and a person in the image would otherwise count as false
   positives.

## Leakage found

1. **The official LIP train and val sets share source photos.** The ID
   `<photo>_<person>` gives it away: 2,508 train crops come from
   photos that also appear in val. Different people are cropped from the
   same photo, and the same pixels often appear in both crops. I confirmed
   this visually.
2. **Near-duplicates.** dHash distance ≤ 6 gives 89,506 candidates. A
   thumbnail correlation threshold, set by looking at samples in each band,
   keeps 991 pairs:

   | Pair | Count | Effect |
   |---|---|---|
   | CIHP train × CIHP val | 197 | 193 CIHP train images excluded |
   | LIP train × LIP val | 12 | (on top of the photo-sharing rule) |
   | CIHP train × train, LIP train × train | 661, 33 | groups merged, no exclusion |
   | DFMM × DFMM, different outfit IDs | 65 | outfit groups merged (some are pixel-identical photos under 2 IDs) |
   | LIP/CIHP val × val (inside the test sets) | 20 | kept: official test sets |
   | LIP ↔ CIHP, any DFMM ↔ LIP/CIHP | 0 | |

3. **Thresholds.**
   - LIP/CIHP pairs: correlation ≥ 0.70. Down to about 0.7 the samples are
     the same photo (re-crops, watermarks, grayscale); below that they are
     different photos.
   - Any pair involving DFMM: ≥ 0.98. Up to that, DFMM pairs are the same
     model and pose in different clothes, and DFMM-vs-LIP/CIHP pairs are
     plain-background false matches (up to 0.73).
4. **Limits of the check.** dHash does not detect crops, so a LIP crop of a
   CIHP photo would be missed. LIP and CIHP have no exact or rescaled
   duplicates between them.

- **DFMM balance:** class presence and sleeve-length distribution are
  similar across DFMM train, val and test (e.g. skirt 8.8 / 8.6 / 10.1% of
  images).
- **The official LIP test set is shifted.** LIP val crops show more of the
  body than train crops: pants appear in 84% of test images vs 52% of
  train, footwear 55% vs 31%. This comes from the official split, not from
  our exclusions. Our LIP val (taken from train) doesn't show the shift,
  so LIP test scores may differ from val scores. Report this in T9/T10.

## Manifest

One row per labelled pair (86,443), excluded rows included. The columns:

- **Identity:** `dataset`, `source_split`, `id`, `split`, `exclude_reason`,
  `group`.
- **Paths:** `image` (relative to `datasets/`), `mask` (relative to
  `data/`).
- **Size:** `h`, `w`.
- **Pixel counts:** `c0`–`c11` and `c255`.
- **DFMM attributes:** 18 raw codes, -1 for non-DFMM rows or missing
  labels. Each attribute's last code means NA, see
  `sources.DFMM_ATTRS`.

## For T4

- `df, meta = load_manifest()` gives the table. Filter with
  `df.split == "train"` and so on; never use `excluded` rows.
- Class weights: sum `c0`–`c11` over train rows only.
- Attributes for E1: map codes in the loader. The last code means NA and -1
  means missing; both go to the ignore value. The choice of heads (Q1) is
  still open; T1 recommends sleeve length and lower-garment length.
- Q2 (sampling ratio across datasets) is still open. Train has about
  26k LIP, 27k CIHP and 10k DFMM images.
