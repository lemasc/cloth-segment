# Handoff — M5 Class-merge view in the T1 EDA notebook (lemasc)

## In plain words
Added section 4b to `notebooks/eda/t1_eda.py`. For every shared class it shows which raw classes merge into it and how much each one supplies.
It shows that `accessory` is a mix: gloves in LIP, scarves in CIHP, and glasses plus neckwear in DFMM.
No label, mapping or split changed. Nothing was trained.

## Summary
- `src/cloth_segment/data/composition.py`: `merge_composition(counts, dataset)` builds the table from the scan counts and the existing `MAPPING`. It only reads `labels.py`.
- `tests/test_composition.py`: synthetic counts only; checks the ratios, the sum to 100, the `ignore` rows, and that empty input gives 0 and not NaN.
- Notebook section 4b: a scope dropdown (`all scanned`, or `train`/`val`/`test` from the `splits-v2` manifest), one table per dataset, and a stacked bar chart per dataset.
- Why a new task: T1 and T2 are `done`. Following the M3/M4 precedent I added a maintenance row `M5` to `PLAN.md` instead of reopening them.

## Decisions and why
- Logic is in `src/` (conventions: notebooks present, they do not define logic).
- The shared contract `labels.py` is not touched, so no version bump.
- Counts come from the T1 scan (`data/eda/scan_*.csv`). The `manifest.csv` of `splits-v2` has shared counts only, so the manifest is used just to pick image ids for a scope.

## Results / findings
Scope `all scanned`, from the scan files. Share of the shared class's pixels that each raw class supplies:

| shared class | LIP | CIHP | DFMM |
|---|---|---|---|
| accessory | glove 49.4%, scarf 33.5%, sunglasses 17.1% | scarf 66.4%, glove 20.3%, sunglasses 13.3% | eyeglass 57.6%, neckwear 40.6%, tie 1.8%, gloves 0 (0 images) |
| footwear | shoes 82.8%, socks 17.3% | shoes 77.1%, socks 22.9% | footwear 90.3%, leggings 7.4%, socks 2.4% |
| dress | dress 72.1%, jumpsuits 27.9% | dress 100% | dress 79.8%, rompers 20.2% |
| skin | arms 85.3%, legs 14.7% | arms 59.6%, torso_skin 26.8%, legs 13.7% | skin 100% |

DFMM `ignore` is bag 51.6%, belt 27.4%, necklace 9.6%, wrist_wearing 8.1%, ring 3.2%, earrings 0.15%.

`accessory` is about 0.39% of LIP pixels, 0.30% of CIHP and 0.016% of DFMM, so DFMM glasses supply very little of the class overall. This matters for the T6 retrain report (`accessory` collapse on DFMM).

## Gotchas
- Pixel counts are over raw masks, before any resize.
- The scope `all scanned` includes images that `splits-v2` excludes. Use `train` to see what the model is trained on.
- Re-run the export check with `uv run marimo export html notebooks/eda/t1_eda.py -o <file>`; it needs `data/eda/scan_*.csv` and `data/splits/splits-v2`.
