# Handoff — E1 Multi-task: segmentation + DFMM attribute heads (claude)

## In plain words
I added `segformer_b2_mt`: the SegFormer-B2 from T8, plus small heads that predict 12 DFMM shape attributes (sleeve length, cardigan, neckline, ...) from the same encoder. Both tasks are learned together.
The segmentation part, its config and the checkpoint rule are the same as X4. Attributes are scored separately (`attr-v1`, next to a majority-class baseline), so each task gets its own result, as the rubric asks.
This task is code only. Training is a new X row (X5), compared with a plain SegFormer run on the same GPU (X6).

## Summary
- `src/cloth_segment/attributes.py`: the head spec read from `model.attr`, target remapping (`ignore_values`), the masked attribute loss, and metrics (accuracy, macro-F1, majority baseline).
- `src/cloth_segment/models/multitask.py`: `segformer_b2_mt`. `forward(x)` returns segmentation logits only, and `forward_multi(x)` returns segmentation plus attribute logits from a single encoder pass.
- `src/cloth_segment/models/wrappers.py`: `PadToMultiple.pad` / `.restore` split out of `forward`, so the multi-task model uses the same padding. Behaviour is unchanged: all model tests pass.
- `src/cloth_segment/train.py`: for a model with `forward_multi`, the loss is `L_seg + loss_weight × L_attr`. It logs `seg_loss`, `attr_loss` and `attr_images`, plus attribute macro-F1 on DFMM val at each check. `meta.json` gets `best_val_attr_mean_macro_f1`. Segmentation-only models take the same code path as before.
- `src/cloth_segment/attr_eval.py`: `python -m cloth_segment.attr_eval <run> --wait` writes `eval/attr-v1/dfmm/attr_metrics.json` (model and majority baseline).
- `configs/segformer_b2_mt.yaml` and `tests/test_attributes.py` (24 tests).

## Decisions and why
- **Single model, SegFormer-B2:** our strongest model, and E1 vs X4 is a clean with/without comparison. The rubric needs 2 tasks in one model, not 3 models.
- **The 12 shape attributes, no texture:**
  - every shape head has at least 1,094 labelled test images;
  - several map onto our errors: `outer_cardigan` (outer↔upper), `lower_length` and `waist_acc` (skirt/dress/pants), and `sleeve`, `neckline` and `covers_navel` (the upper garment);
  - texture is very skewed (`fabric_upper` is 81% cotton), has 3–5 values with fewer than 20 test images, and the outer-garment ones are 80% NA.
- **Rare values:**

  | head | value | train / val / test | handling |
  |---|---|---|---|
  | sleeve | not_long | 6 / 0 / 0 | ignored (T1: ill-defined) |
  | glasses | in_hand_or_clothes | 16 / 3 / 5 | ignored (not worn) |
  | glasses | eyeglasses | 0 / 0 / 0 | logit kept, never seen (M6: DFMM glasses are sunglasses) |
  | neckline | square | 93 / 8 / 10 | trained; left out of the headline F1 (< 20 test) |

- **Every E1 setting lives under `model.attr`, including the loss weight.** `loss` and `eval` are shared comparison fields (D5). This way E1 differs from X4 only in `model.*`. A test checks this and checks that the hashes of existing runs did not change (X4 `8e9039649376`, X2 `d4f03d515ed0`).
- **Loss weight 0.1:** X4's segmentation CE ends near 0.31, and the attribute CE runs about 0.6–0.9 (smoke run). 0.1 keeps the attribute term well below segmentation, to protect it. It is not tuned.
- **Head:** stage-4 encoder feature (512 channels), average and max pooling, a 256-unit layer with GELU and Dropout 0.2, then one linear layer per head. It adds 272,166 parameters (+1.0%; total 27,628,018).
- **Initialisation:** the head is built after the SegFormer builder, so with the same seed the segmentation weights start the same as X4 (M4, tested).
- **Checkpoint:** `best.pt` still follows `dataset_mean_miou`. Attribute val is monitoring only.
- **Headline F1:** macro-F1 only over classes with at least 20 true test images (`MIN_COUNT`). `macro_f1_present` (all classes present) is also reported.
- **Sampling stays natural:** about 1.30 DFMM images per batch on average, and 24% of batches have none. Empty batches give a zero loss that keeps the graph intact.

## Results / findings
No training run in this task.
- **Majority baseline on DFMM test** (from the new code, `splits-v2-d023252b81d9`): mean macro-F1 **0.331**, mean accuracy 0.694 over the 12 heads. Accuracy alone is misleading: predicting "no" already scores 0.951 on `glasses` and 0.890 on `socks`.
- **GPU smoke run** (40 steps, RTX 4070, bf16, batch 8; scratchpad, not `runs/`):
  - peak memory 9,235 MiB (X4 probe: 9,019);
  - 0.204 s/iteration, so about 2.3 h for 40k steps;
  - 1.4–1.8 labelled images per batch;
  - `attr_eval` on that checkpoint wrote a full metrics file (1,293 images).

## Gotchas
- An E1 checkpoint has `attr_head.*` keys, so load it with `segformer_b2_mt` (`evaluate.load_model` does this from the run's config).
- `evaluate.py`, `errors.py` and `rawclass.py` work on E1 runs unchanged, because `forward` returns segmentation only.
- A smoke run with few iterations needs `optim.warmup_iters` below `train.iters` (base is 1500).
