Pixel share: background is 53% (LIP), 61% (CIHP), 77% (DFMM). Belt, sunglasses,
gloves, scarf and socks are each ~0.1% of pixels → strong class imbalance.

Domains differ: LIP = one-person crops from the wild; CIHP = multi-person
scenes; DFMM = studio fashion. Train-on-A → test-on-B is a natural analysis (E2).

## Proposed repo layout (not created yet)

```

```

Run folder: `config.yaml` (resolved), `meta.json` (commit, dirty flag,
config_hash, data_version, seed, env, user), `ckpt/{best,last}.pt`, logs,
`eval/<test_set>/metrics.json`, `DONE`. The folder is named at start as
`<YYYYMMDD-HHMM>-<shortcommit>[-dirty]-<slug>`. Cache lookup scans
`runs/*/meta.json` for `config_hash`. The lock is taken at start, so a run in
progress also blocks a duplicate.

## Data-processing checklist (for T1–T4)

- Masks: load as `L`/`P`, never convert to RGB; resize with nearest only; never JPEG.
- Every source value must be mapped explicitly (to a shared class or 255); fail on unknown values.
- Check every image/mask pair for matching size; check EXIF orientation; convert images to RGB; find corrupt or all-background files.
- LIP and CIHP ID 10 mean different things: map them separately.
- Evaluate at the original mask resolution; use 255 as ignore in both loss and metrics.
- Use the same ImageNet normalisation for every model, via our own transforms (not each library's image processor).
- Compute class frequencies and weights on the train split only.
- DFMM: group split by outfit ID; check for duplicate images across datasets (perceptual hash).
- Keep the original images; write converted masks + manifest. No pre-resizing to the training resolution (an optional decode-speed cache must have its own version).
