## In plain words

1. เพิ่ม U-Net ส่วน encoder (ส่วนที่ย่อรูปเพื่อหาลักษณะเด่น) เป็น ResNet-34 ที่เรียนจาก ImageNet มาแล้ว ส่วน decoder (ส่วนที่ขยายผลกลับเป็นขนาดรูป) เริ่มเรียนใหม่ ลงทะเบียนเป็น `unet_r34` ใน registry ของ T5
2. Baseline: test mIoU LIP 0.5539, CIHP 0.5756, DFMM 0.7736 (eval-v1) คลาสที่ IoU ต่ำที่สุดในทั้ง 3 ชุดคือ accessory ตามด้วย skirt
3. val mIoU ยังขึ้นอยู่ตอน 40k ทีมต้องตัดสินว่าจะขยายเป็น 80k หรือไม่

  ถ้า output เล็กกว่ารูปเข้าจะขยายแบบ bilinear แล้ว crop กลับเป็นขนาดเดิม

  `smp.Unet("resnet34", classes=NUM_CLASSES, activation=None)` ห่อด้วย

- `configs/unet_r34.yaml`: มีแค่ `model.name: unet_r34` และ `model.pretrained: true`
- `tests/test_models.py`: 23 test รันบน CPU ไม่ต้องโหลด weight (ใช้
  `pretrained: False`)
- dependency: `segmentation-models-pytorch>=0.6.0` (lock ไว้ที่ 0.6.0 ใน
  `uv.lock` ดึง `timm==1.0.31` มาด้วย) อยู่ใน `main` แล้ว ไม่ใช่ dependency ใหม่ของ
  PR นี้ torch ยังเป็น 2.14.1

Interface ของทุกโมเดล: รับ `[B, 3, H, W]` ที่ normalise แบบ ImageNet แล้ว
คืน logits `[B, 12, H, W]` ไม่มี softmax

## Decisions and why

- **smp แทนการเขียน decoder เอง:** ลดความเสี่ยงบั๊กใน decoder ที่เขียนเอง
  encoder ไม่ใช่ตัวเดียวกัน ตาม PLAN U-Net (T6) ใช้ ResNet-34 และ DeepLabV3+
  (T7) ใช้ ResNet-50 ความยุติธรรมตาม D5 มาจากการใช้ encoder ที่ pretrained บน
  ImageNet จากแหล่งเดียวกัน (smp) และ pipeline เดียวกัน (data, split, ความละเอียด
  ภาพ, augmentation, จำนวน iteration) ขนาดโมเดลจึงต่างกัน ต้องรายงานจำนวน
  พารามิเตอร์ (จาก `count_parameters`) คู่กับผลทุกครั้ง
- **Pad แล้ว crop แทนการ resize (ป้องกันเพิ่ม):** ตรวจแล้วว่า smp 0.6.0 รับ H, W
  ที่หาร 32 ไม่ลงตัวได้เอง (ทดสอบ `smp.Unet` เปล่ากับรูป 100×75 ได้ logits 100×75)
  และ pipeline ส่งรูป 512×512 เสมอ `PadToMultiple` จึงเป็นแค่การป้องกันเพิ่ม เผื่อ smp
  เวอร์ชันอื่นหรือขนาดรูปอื่น การ pad ไม่เปลี่ยนพิกเซลเดิม จึงได้ logits ตรงตำแหน่งกับ mask
  pad ด้วย 0 เพราะหลัง ImageNet normalisation ค่า 0 คือสีเฉลี่ย
- **Normalisation อยู่ใน data transforms (T4) ไม่ได้อยู่ในโมเดล** ตาม checklist ใน
  kickoff handoff ใช้ค่าเดียวกันกับทุกโมเดล
- **`NUM_CLASSES` มาจาก `data/labels.py`** ไม่ได้อยู่ใน config จึงตรงกับ label set เสมอ
- **ชื่อโมเดลที่ไม่รู้จัก** (รวมถึง `null` ใน `base.yaml`) จะ raise `ValueError`
  (จาก `build_model` ของ T5) ส่วน key อื่นใต้ `model:` ที่ builder ไม่ใช้ จะไม่ถูกเช็ก
  (`unet_r34` อ่านแค่ `pretrained`)

## Gotchas

- smp 0.6.0 รับ H, W ที่หาร 32 ไม่ลงตัวได้เอง (ทดสอบ 100×75 แล้ว) `PadToMultiple`
  เป็นการป้องกันเพิ่ม ถึงอย่างนั้นให้สร้างโมเดลผ่าน `build_model` เสมอ อย่าเรียก
  `smp.Unet` ตรง ๆ เพราะ checkpoint ถูกบันทึกจากโมเดลที่มี wrapper (ดู prefix `net.` ด้านล่าง)
- key ใต้ `model:` ที่ builder ไม่ใช้จะไม่ถูกเช็ก ถ้าพิมพ์ผิด (เช่น `pretrain: false`)
  จะไม่ error และใช้ค่าเริ่มต้นแบบเงียบ ๆ (`pretrained: true`) ตรวจชื่อ key ให้ดี
- ตอน inference ต้อง normalise รูปด้วย transform ของ T4 (`data/transforms.py`,
  ImageNet mean/std) เพราะโมเดลไม่ได้ normalise เอง ถ้าส่งรูปดิบ (0–255 หรือ 0–1)
  จะไม่ error แต่ผลจะผิด
- โมเดลข้างในเข้าถึงได้ที่ `model.net` (มี `.encoder`, `.decoder`,
  `.segmentation_head`) เช่น ถ้า T5 อยากตั้ง learning rate ของ encoder แยก
- สมาชิกแต่ละคนบนเครื่องกลางจะดาวน์โหลด weight เองครั้งแรก (84 MB) เพราะ cache
  อยู่ใน home ของแต่ละคน ถ้าเครื่องเทรนออกเน็ตไม่ได้ ให้ดาวน์โหลดไว้ก่อน
  แล้วตั้ง `HF_HUB_OFFLINE=1`
- Checkpoint ของ U-Net ที่เทรนแล้วจะมี prefix `net.` ใน state dict เพราะมี wrapper ห่อ
- Baseline run นี้สุ่มค่าเริ่มต้นของ decoder และ head โดยไม่ใช้ seed เพราะ `train.run` เรียก
  `build_model` (`train.py:236`) ก่อน `torch.manual_seed` ใน `fit` (`train.py:139`) ผลยังใช้ได้
  แต่รันซ้ำแล้วจะไม่ได้ค่าเริ่มต้นเดิม ทั้งที่ `meta.json` เขียนว่า `seed: 0` ต้องแก้ใน `train.py`
  (โค้ดของ T5) ก่อนเทรนรอบถัดไป
