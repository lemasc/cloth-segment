# รายงานการเทรน: SegFormer-B2 (X4)

## In plain words
เทรน SegFormer-B2 (โมเดลจาก T8) ด้วย config ร่วมเดียวกับ U-Net ครบ 40,000 iteration บน RTX 3060
ผล test mIoU: LIP **0.6155**, CIHP **0.6295**, DFMM **0.8425** (eval-v2, `best.pt` step 40000)
สูงกว่า U-Net (X2) ทุก test set และทุกคลาส ถ้าไม่นับ `accessory` ก็ยังสูงกว่า 0.045 แต่เป็นแค่ 1 run ต่อโมเดล
`best.pt` อยู่ที่ step สุดท้ายอีกครั้ง และ val ยังขึ้นอยู่ตอนจบ (ดูเงื่อนไขของ M7)

ตัวเลขทุกตัวมาจากไฟล์ใน run folder (`meta.json`, `log.jsonl`, `eval/eval-v2/*/metrics.json`)
ตัวเลขของ X2 มาจาก [`2026-11-05-T6-unet-r34-retrain.md`](2026-11-05-T6-unet-r34-retrain.md) เพราะ run folder ของ X2 อยู่อีกเครื่อง

## ตรวจหน่วยความจำก่อนเทรน (probe)

## การตีความ
- **X4 สูงกว่า X2 ทุก test set และทุก 36 คู่ (คลาส × test set)** คลาสที่ขึ้นมากรองจาก `accessory` คือคลาสเสื้อผ้าที่ยาก
  ได้แก่ `dress`, `skirt` และ `headwear` (+0.05 ถึง +0.10 ทุก test set) และ `footwear` บน CIHP (+0.1009)
  ส่วนคลาสที่ง่ายอยู่แล้ว (`background`, `face`) ขึ้นน้อย
- **ความต่างใหญ่กว่าความแกว่งระหว่าง run ที่เคยวัด** X2 เทียบกับ X1 (config เดียวกัน) ต่างกันประมาณ 0.01
  (val เฉลี่ย −0.0129, test 12 คลาส −0.0096) ส่วน X4 − X2 คือ +0.0711 (12 คลาส) และ +0.0450 (11 คลาส)
  ตัวเลข 0.01 มาจากแค่ 2 run และ X4 มี run เดียว จึงยังพูดไม่ได้อย่างเป็นสถิติ แต่ห่างกันหลายเท่า
- **ส่วนใหญ่ของความต่างไม่ได้มาจาก `accessory`** ถ้าไม่นับคลาสนี้ ยังต่าง +0.045
  `accessory` ทำให้ 12 คลาสห่างเพิ่มอีกประมาณ 0.026 และ X4 เรียน `accessory` ได้ตั้งแต่ 4k ต่างจาก X2
  เหตุผลยังไม่รู้ อาจเป็นสถาปัตยกรรม (attention ที่เห็นภาพกว้าง) หรือ seed ยังไม่ได้ทดสอบ
- **ยังไม่ใช่ผลเทียบ 3 โมเดล** X3 (DeepLabV3+) ยังไม่ได้รัน การเทียบอย่างเป็นทางการเป็นงานของ T9

### สิ่งที่ทำให้การเทียบกับ X2 ไม่ตรงกันทุกอย่าง
- **GPU คนละรุ่น** (3060 เทียบกับ 4070) การคำนวณบน GPU ไม่ deterministic เต็มที่อยู่แล้ว ผลของการเปลี่ยนรุ่นยังไม่ได้วัด แต่น่าจะอยู่ในระดับความแกว่งระหว่าง run
- **optimizer ไม่ใช่สูตรต้นฉบับของ SegFormer** (ต้นฉบับใช้ lr 6e-5, head lr ×10, ไม่ใช้ weight decay กับ norm) ทุกโมเดลใช้ lr 1e-4 เท่ากัน (ตัดสินใน T8 ดู handoff ของ T8)
  ผลนี้จึงเป็นการเทียบภายใต้สูตรเดียวกัน ไม่ใช่ผลที่ดีที่สุดของแต่ละโมเดล

## เงื่อนไขของ M7
M7 ล็อกงบไว้ที่ 40k "reopen only if X3 `best.pt` is step 40000 again" เงื่อนไขนี้เขียนสำหรับ X3 ไม่ใช่ X4
แต่ X4 เป็นแบบเดียวกัน คือ `best.pt` = step 40000 และ val เฉลี่ยยังขึ้น +0.0054 ใน 4k สุดท้าย (ตอน lr ลดเกือบเป็น 0)
ข้อมูลนี้แจ้งให้ maintainer ใช้ประกอบการตัดสินใจ ไม่ได้เสนอให้เปลี่ยนงบ

## สิ่งที่ยังไม่รู้
- ความแกว่งระหว่าง seed ของ SegFormer (มี run เดียว)
- ผลของการเปลี่ยน GPU จาก 4070 เป็น 3060 ต่อตัวเลข
- ทำไม X4 เรียน `accessory` ได้เร็วกว่า X2 มาก
- ผลที่ 80k หรือกับสูตร optimizer ต้นฉบับ
- ทำไม smp ใช้หน่วยความจำมากกว่า HF 4%

## งานต่อ
1. **X3:** เทรน DeepLabV3+ เพื่อให้ครบ 3 โมเดล แล้วดูเงื่อนไขของ M7
2. **T9:** ตารางเทียบ 3 โมเดล (12 และ 11 คลาส, `accessory` แยก)
3. **T10:** เขียนข้อจำกัด: lr ร่วมแทนสูตรต้นฉบับ, 1 seed ต่อโมเดล, X4 รันบน GPU คนละรุ่นกับ X1–X3
4. ย้าย run folder นี้ไป shared mount (D7) ตอนนี้อยู่แค่ใน `lemasc-ubuntu` ให้ maintainer ตัดสินวิธี
5. (follow-up) ให้ `scripts/probe_memory.py` ใช้ builder ตัวจริงจาก `cloth_segment.models` แทน builder ชั่วคราว
