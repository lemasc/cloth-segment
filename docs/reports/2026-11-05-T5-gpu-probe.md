# GPU probe: หน่วยความจำและความเร็วของ 3 โมเดล (T5)

## In plain words
วัดว่า GPU ของเครื่องทีม (RTX 4070, 12 GB) รับ batch ได้เท่าไรสำหรับแต่ละโมเดลที่ input 512×512
SegFormer-B2 หนักที่สุด รับได้สูงสุด batch 8 (batch 12 หน่วยความจำไม่พอ) จึงตั้ง batch 8 ให้ทุกโมเดล
และตั้ง budget 40k iteration ซึ่งคำนวณแล้วใช้เวลา GPU ประมาณ 4.4 ชั่วโมงสำหรับ 3 โมเดล (ยังไม่รวมเวลา eval)

## วิธีวัด
- สคริปต์: `scripts/probe_memory.py` (โค้ดอยู่ใน `src/cloth_segment/probe.py`) ที่ commit `942281f`
- คำสั่ง: `uv run python -u scripts/probe_memory.py --out probe.json`
- ผลดิบ: [`2026-11-05-T5-gpu-probe.json`](2026-11-05-T5-gpu-probe.json) (ไม่มี run folder เพราะไม่ใช่การเทรน)
- เครื่อง: NVIDIA GeForce RTX 4070, 12,282 MiB, torch 2.14.1+cu126, บน WSL
- แต่ละ (โมเดล, batch): รันการเทรนจริง 5 รอบ warm-up แล้วจับเวลา 20 รอบ
  - 1 รอบ = forward → ขยาย logits เป็น 512 → cross-entropy (ignore 255) → backward → AdamW step
  - AMP bf16, input 512×512 (จาก `configs/base.yaml`), 12 class
  - ภาพและ mask เป็นค่าสุ่ม ใช้ได้เพราะ train transform ตัดภาพเป็น 512×512 เสมอ หน่วยความจำจึงไม่ขึ้นกับภาพ
  - น้ำหนักโมเดลสุ่ม (ไม่ใช่ pretrained) ไม่มีผลต่อหน่วยความจำหรือความเร็ว
  - AdamW เก็บ state มากกว่า SGD ผลนี้จึงเป็นกรณีที่ใช้หน่วยความจำมากที่สุด
- ตอนวัดมี process อื่นใช้ GPU อยู่ 1,188 MiB สคริปต์จึงจำกัดหน่วยความจำไว้ที่ส่วนที่ว่าง **11,094 MiB**
- "peak MiB" = `torch.cuda.max_memory_allocated()` (หน่วยความจำที่ PyTorch จองจริง ไม่รวม CUDA context)

## สิ่งที่เห็น
- **SegFormer เป็นตัวกำหนด batch:** ที่ batch เท่ากันใช้หน่วยความจำมากกว่า U-Net ประมาณ 3.5–4 เท่า
  และช้ากว่าประมาณครึ่งหนึ่ง ถึงจำนวนพารามิเตอร์จะใกล้กัน สาเหตุน่าจะเป็น attention ที่ความละเอียดสูง (stage แรกที่ 128×128 token)
- **หน่วยความจำเพิ่มเกือบเป็นเส้นตรงตาม batch** ในทุกโมเดล
- **ภาพ/วินาทีแทบคงที่ทุก batch:** GPU ทำงานเต็มที่ตั้งแต่ batch 4–8 แล้ว การเพิ่ม batch จึงไม่ทำให้เทรนเร็วขึ้น
- **data loader ไม่ใช่คอขวด:** loader ทำได้ประมาณ 256 ภาพ/วินาที (T4) เร็วกว่าทุกโมเดล

## การตัดสินใจที่ใช้ผลนี้
ตั้งใน `configs/base.yaml` (commit `3a4bf4a`) เป็น shared comparison field (D5):

- `train.batch_size: 8` คือค่าที่ใหญ่ที่สุดที่ SegFormer-B2 รับได้ ใช้เท่ากันทุกโมเดล
  ไม่ใช้ gradient accumulation เพราะ BatchNorm ของโมเดล CNN จะยังเห็นแค่ 8 ภาพต่อรอบอยู่ดี
- `train.iters: 40000` ประมาณ 5 epoch ของ train set (62,500 ภาพ) จะขยายเป็น 80k ถ้า curve ของ val
  ยังขึ้นอยู่ตอนจบ

## ข้อควรระวัง
- **ที่ว่างเหลือน้อย:** SegFormer ที่ batch 8 ยังเหลือที่ว่างประมาณ 2.4 GB จากเพดาน ถ้า process อื่นบนเครื่อง
  (ซึ่งไม่ผ่าน GPU lock ของทีม) ใช้หน่วยความจำเพิ่ม run อาจ OOM กลางทาง
- **ตอน eval ระหว่างเทรน** จะใช้หน่วยความจำเพิ่มอีกเล็กน้อย ยังไม่ได้วัด
- **WSL ไม่แจ้ง OOM:** ถ้าไม่จำกัดหน่วยความจำ driver ของ Windows จะเอา RAM ของเครื่องมาใช้แทน
  ทำให้ batch ที่ใหญ่เกินช้ามากแทนที่จะ error (รอบแรกที่ไม่ได้จำกัดรันเกิน 15 นาทีแล้วถูกหยุด)
  สคริปต์จึงเรียก `torch.cuda.set_per_process_memory_fraction` ตอน train จริงควรทำแบบเดียวกัน
- **DeepLabV3+ เทรนด้วย batch 1 ไม่ได้** (ASPP pooling) สคริปต์จึงรับเฉพาะ batch ≥ 2
- **ยังไม่ใช่โมเดลตัวจริง:** builder ใน `probe.py` เป็นตัวชั่วคราว ถ้า T6–T8 เปลี่ยน decoder หรือ config
  ของโมเดล ควรรัน probe ใหม่
